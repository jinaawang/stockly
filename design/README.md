# Handoff: Stockly — household shopping & budget app

## Overview
Stockly is a mobile-first web app (iPhone + iPad, installable from Safari) for households that share one weekly shopping list and a monthly grocery budget in Thai Baht. Housemates plan menus, the ingredients land on the list, anyone can check things off (fully or partially), prices can be logged later, unbought items roll into the next week, and a recap goes out Sunday 8pm.

## About the design files
The `.dc.html` files in this bundle are **design references built in HTML**: a fully working prototype that keeps its data in the browser (`localStorage`). They show the intended look, copy, and behaviour. The job is to **recreate them in a real codebase** with Supabase as the backend, not to ship these files as-is. Recommended stack: Vite + React + TypeScript, `@supabase/supabase-js`, deployed as a PWA (Vercel or GitHub Pages). Keep the DOM structure, inline style values, and copy; swap local state for Supabase queries.

## Fidelity
**High-fidelity.** Colours, type, radii, spacing, and copy are final. Reproduce them exactly. Everything comes from the Restock design system (`_ds/` folder: tokens in `tokens/*.css`, React components in `_ds_bundle.js`). The components used: Button, IconButton, Avatar, Tag, Input, Select, Stepper, Checkbox, SegmentedControl, ProgressBar, ShoppingItem, CategoryBudget, TabBar, GradientCard, Sticker, Sheet. Port them as-is into the codebase (source is plain React).

## Interactions & behaviour
- **Week** starts Monday 00:00 local. Weekly budget = monthly × 12 ÷ 52. Currency: `฿` + whole baht with thousands commas, `font-variant-numeric: tabular-nums`.
- **Plan a menu**: for each non-staple ingredient, qty × (portions ÷ recipe portions) rounded to 0.1; merge into an existing unbought item with the same name+unit this week, else insert with `source='menu'`. Removing a menu deletes its unbought `menu` items. Updating portions = remove + re-add.
- **Staples** (`staple=true`) never auto-add. Heuristic for imports: unit `tbsp` or name matches `sauce|paste|oil|sugar|syrup|mirin|flour|rice powder|jasmine rice|sesame seeds|dried shrimp`.
- **Partial buy**: `qty_bought += got`, `bought_by`, `bought_at`; price adds to any previous price for that item. Row shows "x left of y". Done when `qty_bought ≥ qty_needed`.
- **Rollover**: on app open and via cron, items with `week_start < current` and `qty_bought < qty_needed` move to the current week with `rolled_over=true`; one system notification "n things rolled over from last week: a, b."
- **Invites**: pending → the invitee must tap Join. Joining moves them out of their current house; a house with no members left is deleted.
- **Notifications** (text templates, actor's name first): "Jina added 2 L milk to the list.", "Ham bought 3 of 5 tissue paper. 2 still to buy.", "Jina bought 10 pcs eggs for ฿65.", "Ham marked dish soap out of stock. 1 pcs added to the list.", "Jina planned Pad Kra Pow for 2 and added its ingredients to the list.", "Jina invited x@y.com to join X. They'll be asked before they're added.", "Ham joined the house.", "Jina renamed the house to X.", "Weekly recap: …". Push goes to everyone in the house except the actor, filtered by their three preferences.
- **Pull to refresh** on the main scroller (touch only): indicator grows to 120px, trigger at 70px, spinner, refetch, then reload.
- **Push on iPhone**: works only when installed to Home Screen (iOS 16.4+). Flow: `Notification.requestPermission()` → `registration.pushManager.subscribe({ userVisibleOnly: true, applicationServerKey: VAPID_PUBLIC })` → upsert into `push_subscriptions` with the three preference flags. `sw.js` shows the banner.
- **Motion**: screens fade/slide in 320ms `cubic-bezier(.2,.8,.2,1)`; menu cards scale .96 on press; swipe snap 320ms same easing.
- **Thai input**: fonts fall back `Manrope, 'Noto Sans Thai', sans-serif`; search matches English name, Thai name, or any ingredient, case-insensitive (`to_tsvector('simple')` or `ilike` in Supabase).

## State → Supabase mapping
Prototype `localStorage` key `restock.v1` → tables in `supabase/schema.sql`:
`users` → `profiles`; `households[]` → `households` + `household_members` + `household_invites` + `categories`; `menus[].ingredients` → `menus` + `menu_ingredients`; `weekPlans{weekStart:[{menuId,portions}]}` → `week_plans`; `items` → `list_items`; `stock` → `stock_items`; `notifs` → `notifications` + `notification_reads`; push prefs (`restock.prefs`) → `push_subscriptions.notify_*`. Session → Supabase Auth. Subscribe to realtime on `list_items`, `stock_items`, `week_plans`, `notifications`, `household_invites` filtered by `household_id`.

## Deploy checklist
1. **Supabase**: new project → SQL editor → run `supabase/schema.sql` → Storage: create public bucket `menu-photos` → Database → Replication: enable the five realtime tables → Auth: enable Email provider (confirm email optional) → add your deployed URL to Auth → URL configuration.
2. **Push**: `npx web-push generate-vapid-keys`; set `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, `SUPABASE_SERVICE_ROLE_KEY` as function secrets; `supabase functions deploy send-push weekly-recap`; Database → Webhooks: on `notifications` INSERT → `send-push`; cron per the comment in `weekly-recap/index.ts`.
3. **App**: `npm create vite@latest stockly -- --template react-ts`; copy `_ds/` components + tokens, `icons/`, `manifest.json`, `sw.js` into `public/`; env `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`; keep the `<head>` meta from `Stockly App.dc.html` (apple-mobile-web-app-*, theme-color, apple-touch-icon, manifest).
4. **GitHub + hosting**: push the repo; Vercel import (zero config) or GitHub Pages via Actions (`vite build` → `dist`). HTTPS is required for the service worker and push.
5. **Phone**: open the URL in Safari → Share → Add to Home Screen → open from the icon → Household → Turn on notifications.
